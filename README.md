# infra-jon

Infrastructure for a cost-conscious DigitalOcean Kubernetes hobby cluster.

## Ownership

- OpenTofu owns DigitalOcean resources: the project, VPC, DOKS cluster, node pool,
  and container registry.
- Helmfile owns in-cluster platform releases.
- Flux owns application releases declared under `apps/` and reconciles the hobby
  cluster from `clusters/hobby` on the `main` branch.

The default footprint is two `s-1vcpu-2gb` workers in Toronto with a non-HA
control plane. Traefik creates one $12/month DigitalOcean regional HTTP load
balancer shared by every HTTP application. cert-manager is installed with
monitoring disabled. No database, persistent volume, logging stack, or metrics
stack is created by default.

The DigitalOcean Container Registry uses the free Starter tier: one image
repository and 500 MiB of storage. The registry name is `jonsolakis`, so images
use paths such as `registry.digitalocean.com/jonsolakis/my-app:<tag>`.

## Prerequisites

Install the versions in `.tool-versions` with mise/asdf, or install OpenTofu,
Helm, Helmfile, kubectl, doctl, SOPS, age, and just yourself. Install the Flux
CLI with `brew install fluxcd/tap/flux`.

`helmfile diff` also requires the helm-diff plugin. Enabling encrypted
ExternalDNS values requires the helm-secrets plugin; it is intentionally not
needed for the default platform render.

Create a DigitalOcean API token and export it without writing it to this repo:

```sh
export DIGITALOCEAN_TOKEN='...'
```

## Create the cluster

Review `tofu/terraform.tfvars.example`. Copy it to the gitignored
`terraform.tfvars` only if you want to override the defaults.

```sh
just tofu-plan
just tofu-apply
just kubeconfig
```

After the registry has been created, enable DigitalOcean's managed image-pull
integration for the cluster once:

```sh
just registry-integrate
```

The integration creates and distributes pull credentials inside DOKS. Registry
credentials are deliberately not generated by OpenTofu, which keeps them out of
local state.

To push an image from a development machine, authenticate Docker and then tag
and push it:

```sh
just registry-login
docker tag my-app:latest registry.digitalocean.com/jonsolakis/my-app:<tag>
docker push registry.digitalocean.com/jonsolakis/my-app:<tag>
```

Use an immutable commit SHA or image digest for `<tag>` in deployments rather
than `latest`. For CI, create a separate DigitalOcean token and store it in the
other project's CI secret store.

OpenTofu state is local and gitignored to avoid adding a $5/month Spaces bucket
for a single-operator hobby cluster. Back up the state securely. Migrate to a
remote backend before allowing CI or another person to apply infrastructure.

The pod and Service CIDRs are immutable cluster settings. Confirm they do not
overlap any network you plan to connect before the first apply. The configured
custom ranges are `172.20.0.0/16` for pods and `172.21.0.0/19` for Services;
both are required together for DOKS VPC-native networking.

## Install the platform

```sh
just helm-diff
just helm-apply
```

This installs cert-manager and Traefik. It does not create a ClusterIssuer until
you set a real email and enable `letsencrypt.enabled` in the hobby environment.
HTTP-01 validation is the default and therefore needs no DNS API credential.

The optional smoke-test release serves `test.jonsolakis.dev` through Traefik
and requests a production certificate. It is disabled after validating the
complete DNS, ingress, and TLS path.

## Bootstrap Flux

Flux is bootstrapped against the public `jonsolakis/infra-jon` repository and
reconciles `clusters/hobby` from `main`. The GitHub bootstrap uses a read-only
deploy key; the GitHub token used to create that key is not stored in the
cluster. Bootstrap is idempotent and can be rerun to repair or upgrade Flux:

```sh
export GITHUB_TOKEN='...'
flux bootstrap github \
  --owner=jonsolakis \
  --repository=infra-jon \
  --branch=main \
  --path=clusters/hobby \
  --personal \
  --token-auth=false
```

The cluster-level Flux Kustomization waits for the Fantasy Hockey HelmRelease
to become healthy. Flux install and upgrade remediation retries failures and
rolls failed application upgrades back to the last working release.

## Fantasy Hockey Stats

Flux deploys the Fantasy Hockey Stats Helm release from its public Git
repository. The chart source is pinned to commit `48a3d2e` (chart version
`0.1.6`), while the API and web image tags are explicitly pinned in the
HelmRelease. The application runs in the `fantasy-hockey` namespace and is
available at `https://fantasy.jonsolakis.dev`.

The API is fixed at one replica because it uses SQLite. Its data lives on a
1 GiB ReadWriteOnce volume using the `do-block-storage-retain` storage class.
Both the PVC and underlying DigitalOcean volume are retained if the Helm release
is removed; delete them manually only when the data is no longer needed.

The deployment refreshes seasons `20242025` and `20252026` in sequential init
containers. If the NHL API is unavailable, the new API pod does not become ready
and Flux rolls the failed upgrade back while leaving existing SQLite data intact.

DigitalOcean's DOKS registry integration distributes a dockerconfigjson Secret
named `jonsolakis` into the namespace. The HelmRelease references that existing
Secret; registry credentials are never stored in Git.

### Application updates

The application repository builds and pushes immutable commit-tagged images.
Image automation is intentionally disabled. To deploy a new application build:

1. Update the API and/or web image tag in
   `apps/fantasy-hockey/release.yaml`.
2. If the chart changed, update the full commit in
   `apps/fantasy-hockey/source.yaml`.
3. Render and review the manifests, then commit and push to `main`.
4. Flux detects the commit and reconciles it. Run `just flux-status` to inspect
   health or `just flux-reconcile` to request immediate reconciliation.

Do not add this release back to Helmfile. Helmfile and Flux must not manage the
same Helm release.

SnapScheduler takes a CSI volume snapshot every Saturday at 08:17 UTC and keeps
the newest four. The namespace quota allows six snapshots so retention cleanup
has headroom. These snapshots are storage-level, crash-consistent backups;
periodically test a restore before relying on them.

Traefik accepts ordinary Kubernetes Ingress resources and redirects HTTP to
HTTPS. Its dashboard is disabled. All apps should use ClusterIP Services behind
this one ingress controller so they share a single paid load balancer.

## DNS automation

ExternalDNS is off by default. Current ExternalDNS has moved DigitalOcean out of
the core binary and lists a community webhook provider that has no stable release
tags yet. Enabling an unpinned `latest` image would weaken supply-chain
reproducibility, so review and pin an image digest first.

After reviewing the provider:

1. Copy `.sops.yaml.example` to `.sops.yaml` and add your age public recipient.
2. Copy `helmfile/secrets/hobby.sops.example.yaml` to `hobby.sops.yaml`, add a
   narrowly scoped DigitalOcean DNS token, and encrypt it with SOPS. The
   encrypted file is intended to be committed.
3. Add your domain under `externalDns.domains` and set
   `externalDns.enabled: true` in the hobby environment.
4. Pin the webhook image by digest or stable tag before applying.

Install `jkroepke/helm-secrets` before enabling this release so Helmfile can
decrypt the SOPS values at deployment time.

The ExternalDNS policy is `upsert-only`, which prevents accidental record
deletion while the cluster is young.

## Day-to-day changes

```sh
just fmt
just validate
just helm-template
just helm-diff
just gitops-template
just flux-status
```

CI validates OpenTofu, Helmfile, and the Flux Kustomize trees. It never applies
infrastructure or touches the cluster. OpenTofu and platform changes remain
explicit local operations; application changes deploy through Flux after a push
to `main`.
